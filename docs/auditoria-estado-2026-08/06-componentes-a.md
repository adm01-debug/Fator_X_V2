**Escopo:** `skills/`, `datahub/`, `shared/`, `workflows/`, `oracle/`, `security/`, `automation/`, `knowledge/`, `integrations/` — 171 arquivos, ~27.000 linhas.
**Data:** 2026-08-16 · **Método:** leitura de código + grep de importadores + rastreio UI → serviço → tabela/edge function. Documentação do projeto **ignorada** por decisão de escopo.

## Premissa de banco (verificada externamente, tratada como verdade)

215 tabelas em produção, **5 com dados** (`roles`=3, `workspaces`=3, `workspace_members`=3, `user_roles`=1, `notification_templates`=1). Vazias: `agent_skills`, `skill_registry`, `agent_installed_skills`, `documents`, `chunks`, `collections`, `automation_rules`, `automation_logs`, `automation_templates`, `agent_workflows`, `agent_workflow_runs`, `connector_instances`, `connector_registry`, `guardrail_policies`, `kb_articles`. **Zero jobs pg_cron.**

Consequência aplicada em toda a classificação: um componente pode ter código correto de ponta a ponta e ainda assim **nunca ter processado um registro real**. Esses casos aparecem como `IMPLEMENTADO_PARCIAL` com a observação _"dormente — nunca executou"_, nunca como `IMPLEMENTADO_TOTAL`. `IMPLEMENTADO_TOTAL` foi reservado a funcionalidades que não dependem de tabela de negócio vazia (ex.: cálculo local puro, leitura de `pg_stat` do próprio banco, sessão/auth).

## Respostas diretas às perguntas do escopo

- **`skills/` — existe marketplace? catálogo é hardcoded?** Existe e é **real**, não hardcoded. `listSkills()` (`skillsRegistryService.ts:46`) lê `skill_registry` com paginação e filtro server-side; não há array de fallback. Instalação grava em `agent_installed_skills` com guarda de teto e trilha de auditoria. O módulo é o **melhor construído do lote** — e o mais inútil hoje, porque as duas tabelas estão vazias: o marketplace mostra EmptyState.
- **`datahub/` — conecta em quê? há query real?** Conecta em **4 bancos Supabase externos** (`bancodadosclientes`, `supabase-fuchsia-kite`, `gestao_time_promo`, `backupgiftstore`) + 1 marcado hibernado, via edge function `datahub-query` que resolve credenciais por env var (`supabase/functions/datahub-query/index.ts:25-38`). As queries são reais, incluindo joins secundários e cross-db por CNPJ-raiz/email/telefone. **Não valida daqui** se as 8 env vars existem em produção.
- **`automation/`+`workflows/` — engine real ou só desenhista? quem executa?** A engine existe (`workflow-engine-v2`, 377 linhas, com SSE e fallback etapa-a-etapa via `llm-gateway`). **Quem executa: só o usuário, clicando.** Não há disparo automático — `cron-executor` é invocado unicamente de `cronSchedulerService.ts:271` com `source: 'frontend-panel'`, e as migrations que criariam os jobs pg_cron estão todas guardadas por `IF EXISTS (SELECT 1 FROM pg_extension WHERE extname='pg_cron')` — com zero jobs em produção, a extensão não foi instalada e **nenhum agendamento jamais disparou**.
- **`oracle/` — chama LLM de verdade?** **Sim.** `oracleStore.ts:153` → edge fn `oracle-council` → `llm-gateway` (`oracle-council/index.ts:115`) com modelos reais de OpenAI, Anthropic e Google. O que é falso é apenas o card de telemetria "Status do Conselho" (`OraclePage.tsx:114-116`).
- **`security/` — dado real ou métrica fixa?** **Misto, e essa é a parte perigosa.** Reais: postura, 2FA, sessões, rollback/WAL (RPCs do Postgres), red teaming, PII scanner, audit log. Falsos: simulador de guardrails (100 % cliente com metadata forjada), compliance frameworks (fórmula inventada), rate limiting (bug que zera 3 de 4 medidores).
- **`knowledge/` — RAG funciona ponta a ponta?** **Não.** A cadeia de persistência existe (`collections`→`documents`→`chunks`, edge fns `rag-ingest`/`rag-embed-v2`/`rag-rerank`), mas as três tabelas estão vazias e **4 dos painéis da tela são mock puro** (logs, resultados de busca, versionamento, telemetria "Live"), além do painel de configuração que não persiste nada. A tela de conhecimento é, hoje, majoritariamente cenografia.
- **`integrations/` — catálogo real ou lista estática?** **Real.** Os 7 arquivos consultam serviços/edge functions (`a2a-server`, `bitrix24-*`, `whatsapp-*`, tabela `mcp_servers`). Os únicos arrays estáticos são catálogos legítimos (métodos da API Bitrix24). Ressalvas: botão de descoberta de tools MCP sem handler, e `WhatsAppLiveConsole` órfão.
- **`shared/` — componentes órfãos?** Sim: 4 de 45 (`GenerativeUI`, `CitationRenderer`, `DashboardSkeleton`, `PaginationControls`). O resto é infraestrutura viva e amplamente usada.
